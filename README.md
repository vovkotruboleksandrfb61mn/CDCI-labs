# Кіберзахист об'єктів критичної інфраструктури

Лабораторний практикум, КПІ ім. Ігоря Сікорського, ННФТІ, ФБ-61мн.
Варіант 3.

Методичка: [`materials/lab-manual.pdf`](materials/lab-manual.pdf)
(Стьопочкіна, Ільїн, Овчарук, 2023).

## Лабораторні роботи

| № | Тема | Зміст |
|---|------|-------|
| 01 | Оцінювання дієвості політики безпеки на основі аналізу динаміки ризиків | лінійна регресія МНК, довірчий інтервал, регресії Пуассона та негативна біноміальна для лічильників атак |
| 02 | Оцінювання вразливостей ОКІ на основі показника CVSS | CVSS v3.1 для п'яти реальних вразливостей ІІоТ, власний калькулятор звірено з FIRST |
| 03 | Моделювання ОКІ у симуляторі Cooja | мережа RPL із 7 відправників і 1 приймач на Contiki, оцінка споживаної потужності |
| 04 | Моделювання атак на ОКІ у Cooja | DIS-атака на RPL, порівняння енергоспоживання до та після, сценарій без duty cycling |
| 05 | Вдосконалення недоліків протоколів IoT | захист Modbus TCP через TLS 1.3 (OpenSSL), активні атаки на канал, сніфер |

## Структура

```
Labs/NN-<тема>/
    solution.py   розрахунки, рисунки в assets/, числа в data/
    report.md     звіт (YAML front matter для титулки)
    data/          вихідні дані, результати (results.json, логи)
    assets/        рисунки для звіту
    out/           зібраний PDF (git-ом ігнорується)
materials/         методичка
templates/kpi.latex  титульна сторінка (ДСТУ)
```

Лаба 5 також має власний код: `Labs/05-modbus-tls/src/` (C + Python),
`run.sh` відтворює всі сценарії.

## Збірка

```bash
make run        # перерахувати solution.py
make L=01       # зібрати PDF у Labs/01-*/out/
make            # зібрати всі звіти
make check      # перевірити верстку (Overfull \vbox) перед здачею
```

Потрібні `pandoc` і `xelatex` (шрифти Liberation). Python-залежності у `.venv`
(`requirements.lock`). Лаби 3-4 відтворюються з Contiki 2.7 + Cooja,
лаба 5 потребує `gcc` та OpenSSL.
